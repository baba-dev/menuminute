# PR C — Capture Wizard (PR A API)

Owner-only route: /dashboard/menu/import. No new SQL, credentials, public storage or provider calls are added by this package. A permitted menu editor may create a private session, photograph a printed menu on mobile, or choose JPEG/PNG/WebP gallery files. Each source receives its own UUID and zero-based page number. Upload uses PR A's binary API with the explicit selected outlet, preserves an identical source ID for in-page retries, and refreshes server revision after every completion. Existing collecting sessions are discoverable via the authenticated recent-history endpoint; camera File bytes do not survive a page reload, so reserved interrupted uploads require reselecting the same photo. Conflicting content returns PR A's 409 and should be recovered in a new draft rather than overwriting private media.

UI guidance covers glare, focus, clipping, source size and 12-page limits; stored thumbnails use authenticated private GET/blob URLs rather than guessing a public media path. Source files and previews are never put in browser storage. The capture step is functional even without the NVIDIA package: GET /api/menu-imports/engine may return 404 or enabled:false, in which case the wizard shows extraction unavailable without a fake progress indicator. If PR B subsequently ships and is explicitly enabled, the user must consent before POST /process, and the polling display shows persisted queued/processing/needs_review/failed status. Candidate preview is READ-ONLY; actual reviewed edits, menu application and publication belong to a later PR. Cancellation uses the expected server revision. Any missing provider/license stays disabled.

Accept: mobile responsive layout, keyboard-accessible file actions and errors, authenticated outlet selection, private preview, upload retry, consent, and truthful recovery. No PDF client upload (PR A only accepts static image media); PDF ingestion requires a separate reviewed server-side pipeline.
