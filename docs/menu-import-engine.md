# PR B — NVIDIA engine (review-only)

Depends on PR A candidate v1 and persistent private source storage. The browser sends no image directly to NVIDIA. Sources travel from worker-only private media as downsampled inline JPEG to the fixed NVIDIA chat-completions endpoint. Every response is strict JSON-validated, price decimals use the outlet's ISO currency exponent (ambiguous/malformed = null), source IDs are assigned by our code, and no dietary/allergen/ingredient claims are inferred. Only a candidate in needs_review is written; no published MenuDocument or public media is touched.

The configured NVIDIA NIM VLM must accept chat-completions user multimodal text/image_url and emit the JSON payload in the model prompt. Do not assume every catalog model supports the same response-format option or image quota. Integration tests use a fake fetch, with no billable calls.

Fail closed by default: set MENU_IMPORT_NVIDIA_ENABLED=true and NVIDIA_IMPORT_COMMERCIAL_APPROVED=true on web AND worker, provision NVIDIA_IMPORT_MODEL on both and NVIDIA_API_KEY ONLY in root-protected worker environment. Obtain and verify commercial production entitlement independently. NVIDIA developer/trial API access is for development/evaluation, not an automatic license to serve paying end-users. Authenticated GET /api/menu-imports/engine returns an enabled flag, never a credential. Unavailable engine rejects new requests with 503; the user must explicitly consent to off-host provider transmission.

Authenticated outlet editor + expected revision gate enqueue. One PostgreSQL transaction updates status, writes audit and outbox. A restricted worker RPC records one usage attempt by event ID BEFORE provider transmission; final receipt stores request count, provider-reported input/output tokens when available, and sanitized status. A retry after a crash while an attempt is started settles unknown without issuing a second potentially billable request. Provider errors and malformed output are terminal; recover with a new import. Provider usage is accounting only, NOT an invented subscription charge or customer invoice. Limit 20 attempts per organization per day; each import processes at most 12 images. No automatic publishing.

Migration 0010 is append-only; old SQL and journal prefix remain immutable. Validate worker private media ACL, owner-only migration backup and ARM64 cutover separately. Do not enable on production with an unlicensed/trial key.

References: https://docs.api.nvidia.com/nim/reference/llm-apis and https://docs.api.nvidia.com/nim/docs/product

## Dense menus and partial results

- The configured NVIDIA NIM **must** support chat-completions image_url content and the selected output-token limit. `NVIDIA_IMPORT_MAX_OUTPUT_TOKENS` defaults to 4096 (allowed 1024–8192); raise it only after checking the specific model limit. Invalid values stop extraction before provider transmission.
- A user may explicitly split a photograph with two side-by-side columns into two private source photographs before upload. No automatic layout assumption is made; the source cap remains 12. Cropping cannot restore missing detail in very small images.
- One HTTP 2xx response containing malformed or empty JSON can be skipped if a different source yielded a valid candidate. The bad source is recorded in `sourceWarnings`, and the editor must acknowledge missing pages before finalizing or applying the draft. A provider/transport error still terminates the job without silently retrying.
- The editor's import detail endpoint reveals only the RLS-scoped, sanitized existing usage state/code; provider bodies, keys and private paths are never returned. Publishing remains separate from private draft application.

## Reliability and cost controls (migration 0108)

- **Cancel stops spending.** The worker renews its lease before every page, and the database refuses renewal unless the import is still `processing`. A cancelled import therefore sends no further provider request (at most the page already in flight completes).
- **Credits follow requests.** The credits charged at submission are recorded on the import. When it finishes, fails or is cancelled, credits for pages never sent are returned exactly once (audit `menu_import.credits_released`). A page that was sent keeps its credit even when the answer was unusable.
- **Partial results survive provider failure.** If the provider fails (transport error, timeout, non-2xx) after at least one page was read, the candidate keeps those pages. The failing page is flagged `provider_unavailable` and later pages `not_processed`; nothing is retried automatically, and the editor must acknowledge the warnings before confirming. If no page was read the import still fails. A lost lease or a cancel is always terminal, never a partial draft.
- **Truncated output.** When the model stops on the output-token limit (`finish_reason=length`), every complete category and dish is kept (a half-printed dish or variant list is dropped) and the page is flagged `truncated_output`. A truncated page with nothing complete is skipped as `invalid_provider_response`. Smaller crops or `NVIDIA_IMPORT_MAX_OUTPUT_TOKENS` are still the remedy for very dense pages; automatic splitting is not implemented.
- **Cross-page merge.** Categories with the same heading (case, accent and punctuation-insensitive) are merged across pages, and a dish with the same name and no conflicting price is kept once (evidence is combined). Same name with different prices stays as separate entries for the reviewer.
- **Size variants.** Printed sizes/options with separate prices are extracted as variants. The dish's own price is then left blank for the reviewer to choose; it is never derived from a variant.
- **Plain prices.** A price is read when the model omits the `uncertain` flag; only `uncertain: true` or an unparsable value nulls it. Every price is still human-confirmed against the photo.
- **Not implemented:** source regions/bounding boxes (they cost output tokens and are unreliable, so evidence remains page-level with the printed excerpt), PDF input, automatic page splitting, and byte garbage collection.

## Tolerant parsing and clear failures

- **Form, not content.** A provider answer is still validated before anything is stored, but harmless deviations no longer discard the photograph: unknown keys are dropped, a numeric price is read as its string, a blank heading becomes an unreadable heading for the reviewer, a dish with no readable name is omitted, the JSON may sit inside a code fence or a sentence of commentary (or after a `<think>` block), a bare list of categories is accepted, and a multi-part message is joined. Prose with no JSON is still rejected.
- **Printed price decoration.** A currency marker at either end ("₹299", "12.50 USD"), a trailing "/-" and well-formed thousands separators ("1,299", "1,29,900") are removed before the amount is parsed. A decimal comma ("12,50") is ambiguous and stays blank for the reviewer. The evidence excerpt keeps the text as printed.
- **Failure codes mean one thing each.** A worker without the model or key reports `engine_unavailable` (previously `provider_unavailable`), and a stored photo that is missing or altered reports `source_unavailable` (previously `processing_failed`). The wizard explains each code in the owner's words and offers a new import.
- **Refusals say what happened.** `src/modules/menu-import/errors.ts` maps each refusal raised by the import SQL commands to its own sentence. The HTTP status still follows the SQLSTATE as before; only the wording changed. Previously several limits surfaced as the organization module's generic "Invalid domain change… currency changes with existing prices require repricing".
- **Bounded retry of refused pages (owner-approved 2026-11-17).** This supersedes "nothing is retried automatically" for one case only. When the provider answers a page with HTTP 429, 502, 503 or 504 it refused the request before producing a completion, so nothing was billed; that page is sent again up to twice, after 2 s and then 8 s (or the provider's `Retry-After` in seconds, capped at 30 s). The lease is re-checked before every retry, so a cancelled import or a lost lease stops there and is terminal. `usage.requests`, the 12-request cap and credits still count the page once. A timeout, a dropped connection, HTTP 500 and every 4xx other than 429 are **never** repeated, because the provider may have completed and billed the request (or will refuse it again); they behave exactly as before. A page that still fails after its retries follows the existing partial-result rules.
