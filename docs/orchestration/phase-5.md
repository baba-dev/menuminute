## Product release definition

**Guest**: photographic/editorial public menu with search, visible category navigation, honest merchant-authored dietary labels, eligible contextual cross-sells (rules-based, no invented factual claims), item detail/bottom-sheet option selection, safe-area cart, authoritative itemized quote, visible changes requiring reconfirmation, no login, idempotent submit, committed-but-awaiting-acceptance distinction, explicit accepted/preparing/ready/served-or-collected tracking. Free/no-order/out-of-hours/offline menus remain browseable and honest; no fake checkout or guest payment gateway. Paid entitlements gate new orders but preserve useful Free QR browsing.

**Staff**: authorized outlet inbox, accept/decline, expiry, audited cancel, kitchen transitions, dine-in served vs pickup collected; payment at restaurant/counter has independent state. Owner role can delegate within scope. Kitchen-only role cannot accept guest pending work.

**Kitchen first release (C)**: launch only with full outlet-authorized multi-station capability: station setup, routing menu items/order lines to one or more validated prep work units (document exact contract), accepted ticket fanout with unique work IDs, concurrent prep, per-station boards/timers/notes, all-day counters, consolidated expeditor screen and explicit full-order release, staff/device authorization and role revocation, audible alert preference/permission, SSE gap replay/full snapshot/polling fallback and Redis/worker outage recovery. Initial Kitchen Pro release cannot be marketed as complete if multi-station or expeditor exists only as decorative preview. Implement incrementally on branches; ship one integrated feature-gated, tested release.

**Outlet modes**: dine-in and pickup across restaurant/diner, cafe, takeout, cloud kitchen and mixed outlets; separate organization/brand/outlet/service-point entities. One organization may run multiple brands at a shared outlet without cross-tenant privileges. Geography, IANA timezone, local transaction currency, locale and platform USD/INR billing are independent. Do not infer room service, courier delivery or marketplace integration.

## Preserved invariants

- Printed QR token stays stable until explicit scoped administrator revocation/regeneration; temporary guest session and order tracking use separate opaque scope-limited capabilities. A copied QR is not presence proof.
- Immutable published menu release; draft edits cannot retroactively change existing order line snapshots. Revalidate current price, flat variant, add-on group constraints, schedules, sold-out and entitlement on server; show guest a changed quote for explicit confirmation.
- Integer/checked minor-unit money, ISO currency exponent including zero/two/three-decimal, outlet-local transaction currency and immutable price/tax/option/fulfillment snapshots. Never reuse paise-only legacy columns as global money. Tax/discount/service-charge/rounding and local legal fields require approved jurisdiction fixtures before enabling sales.
- Every submitted ticket is a separate order; scoped idempotency key + canonical payload hash reconciles lost responses; a changed payload conflicts. Confirmation only after PostgreSQL commit, not staff acceptance.
- Pending -> accepted -> preparing -> ready -> served (dine-in) / collected (pickup); rejected/cancelled/expired terminal outcomes, authorized/audited changes. Stored closing instant competes atomically with acceptance using DB clock/version; accepted work continues after closing; explicit 24h business cutoff.
- PostgreSQL owns orders, station work, event sequence, audit and outbox. Redis delivery is at least once, never authoritative. SSE gaps trigger bounded replay or full scoped snapshot; polling fallback; staff revocation invalidates event/read/command access. Never replay offline orders automatically.
- Multi-station item work is unique and recoverable; one station done never means order ready when another is pending. Completion rule requires all required work plus authorized expeditor release (unless separately approved explicit single-station policy). Station routing/version and subsequent reassignment cannot silently rewrite ongoing work. Kitchen actions do not imply payment or guest acceptance.
- Any AI suggestion remains reviewable; no AI/inference on checkout/kitchen critical path, no invented ingredient/allergen claims, no automatic image publication.

## Design-in-PR acceptance

Each feature PR includes desktop/mobile actual rendered evidence, not a brochure: 360, 390, 768, 1024 and 1440 px plus tablet landscape where relevant; Light/Dark/System before first paint; WCAG 2.2 AA target, focus/keyboard/200% zoom, 44px touches, long names/Hindi where enabled, reduced-motion, safe-area cart/sheets, theme-specific original food illustration/approved photo fallbacks. Product owner reviews screenshot+flows directly on PR and can request visual changes there. Shared Ink & Ember semantic tokens/primitives remain canonical: vivid white/orange/gold light; charcoal/gold/orange dark; Ember Flow ordinary, Ink Press sparse focal, Service Card routine, Ink Ticket milestone, Chef's Note optional only. Sound cannot activate automatically and permission denial must preserve visual notifications. Error/uncertain/disconnected states are durable, never toast-only. Order/kitchen actions confirm only after server commit/version match.

## Operations and explicit exclusions

Native Linux ARM64/Node 24 separate from ERP Node 20; no builds/migrations on shared VPS through CI, do not change ERP PM2/port 3000/Nginx vhost. All migration-changing artifacts stage only pending reviewed operator SQL, backup, approval and compatibility; latest-main unchanged-migration verified build may use existing approved deployment path. Never treat a GitHub PR merge as production success. Confirm both web/worker exact SHA, immutable package digest, public readiness, ERP HTTP before/after, backup/alert and **disposable matching SQL + private media restore**. Load against the planning 25-owner/50-outlet/1k-order/hour fixture with bursts, public reads, station updates/SSE and one noisy tenant, with agreed thresholds and ERP measurement.

Out of Phase 5: online guest payments, courier delivery, hotel room-service lifecycle, third-party marketplace/POS bridges, shared bill splitting, loyalty, autonomous AI pricing/claims, nested combos and size-dependent add-on rules without approved examples, scheduled pickup before separate decision, speculative advertised ₹149/₹299 or unapproved USD tariff. Free menus and printed QRs survive paid expiry; finishing already accepted work remains possible.
